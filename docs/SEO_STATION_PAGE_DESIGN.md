# 駅静的ページ / SEO 設計

## 目的

駅詳細をJavaScriptモーダルだけで表示する構造から、駅ごとに恒久URLを持つ静的HTMLへ移行する。

主商品は「総合点」ではなく、駅中心1km圏の現在と将来人口、暮らし、交通、不動産取引を意思決定に使える形で並べることとする。

## URL

- 駅一覧: `/station/`
- 駅詳細: `/station/<XKT015グループコード>/`
- canonical IDは駅グループコードとし、駅名変更や同名駅でURLが揺れないようにする。

## 生成

`web/data/geo/index.json` と `web/data/geo/station/<code>.json` を入力に、DBへ接続せず次を生成する。

- `web/station/index.html`
- `web/station/<code>/index.html`
- `web/sitemap.xml`
- `web/robots.txt`

通常のデータビルドでは `scripts/build_site.py` が生成する。GitHub Pages公開時は、コミット済み公開JSONから `scripts/build_public_pages.py` が毎回再生成する。

## index品質ゲート

総合点はindex条件にしない。取引件数不足で総合点が出ない駅でも、将来人口・生活・交通の判断材料が揃えばページ価値があるため。

indexに必要な条件:

- 駅コード・駅名
- 中心座標
- 1km圏メッシュ1件以上
- 2025年推計人口
- 2045年推計人口
- 生活施設または交通の有効データ
- 出典情報

不足時もページ自体は生成するが `noindex,follow` とし、sitemapから除外する。

## ページの情報順

1. 駅名・1km圏定義・信頼度
2. 2025→2045将来人口
3. 不動産取引の推移
4. 生活施設
5. 交通
6. 参考スコア
7. 関連ページ・出典

総合点は「参考総合評価」として主役から降ろす。

## 不動産取引の注意

XIT001の駅コード指定データは「駅から1km以内に存在する物件」と定義しない。駅グループコードを検索条件として取得できた取引として表示し、駅1km圏の空間集計と混同しない。

## 次段階

駅1km圏に対して既存の250mメッシュ・災害レイヤーを再利用し、人口維持率、洪水、液状化、地震、標高を同一ページで切り替えられる駅メッシュ地図を追加する。
