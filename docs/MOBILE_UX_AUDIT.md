# スマホUX総点検

対象: `web/index.html` / `web/stations.html` / `web/ward.html`

目的は、スマホで「探す → 候補を見る → 保存する → 比較する → 詳細を確認する」までを片手操作でも破綻させないこと。物理端末そのものをこの環境から操作することはできないため、iPhone Safari / Android Chrome の実機制約を前提に、320–430px幅・タッチ操作・ソフトウェアキーボード・sticky要素・横スクロール・初期データ転送を中心にコードとUI構造を総点検した。

## P0 / すぐ直す項目

- **iOS入力時の勝手な拡大**: 16px未満の `select` / `number` 入力をスマホ時16pxに固定。
- **区詳細のsticky二段重なり**: スマホではサイトヘッダーが2段になるのに、区内目次が `top:68px` 固定だった。700px以下では区内目次を通常フローへ戻し、本文との重なりを防止。
- **タップ領域不足**: プリセット、候補保存、比較、フィルター追加、ダイアログ閉じる等を40–44px以上へ拡大。rangeも44pxの操作高さを確保。
- **ランキングの横スクロール過多**: スマホでは順位・地域/駅・現在選択中の評価・信頼度に絞る。詳細比較は既存の詳細画面/条件比較へ委ねる。
- **長いダイアログ**: `100dvh` 基準で高さを制限し、画面外へはみ出さないようにする。

## P1 / 読みやすさ・迷い防止

- **ヘッダーナビ**: 横スクロールを許可し、スクロールバーを隠しつつ44pxのタップ高さを維持。
- **アンカー移動**: stickyヘッダー分の `scroll-padding` / `scroll-margin` をスマホ幅で補正。
- **小さすぎる補足文字**: おすすめ理由、注意点、候補保存メッセージ、駅おすすめ補足をスマホ時11px以上へ引き上げ。
- **条件比較表**: 横スクロール中も区名をsticky表示し、どの地域の行か見失わないようにする。
- **検索候補**: ソフトウェアキーボード表示中でも結果欄が画面を占有しすぎないよう `dvh` で高さを制御。
- **ファーストビューの縦長化**: 520px以下では「街選びの流れ」の説明文を省略し、主要CTAとおすすめ検索へ早く到達できるよう圧縮。
- **同じJSONの重複取得**: `explore/wards.json` は約183KB、駅indexは約333KB。ホームでは複数モジュールが同じJSONを `no-store` で読むため、同一ページ内の同URL GETを1回のレスポンスへ集約し、各利用側へ `clone()` を返す。ページ再読込時の鮮度は維持する。

## P2 / タッチ端末特有の挙動

- hover専用の浮き上がり演出を coarse pointer では無効化し、タップ後にカードが不自然に浮いたまま見える挙動を避ける。
- 250mメッシュ上では縦スクロールとピンチズームをブラウザへ許可し、地図領域がページスクロールを邪魔しにくくする。
- `prefers-reduced-motion` を尊重し、スムーズスクロール/トランジションを抑制できるようにする。

## 実機で最終確認する観点

物理端末確認時は以下だけを重点的に触ればよい。

1. iPhone Safari: 条件フィルター・比較selectを触ってもページが拡大しない。
2. 320/375px: ヘッダー内リンクが潰れず横に送れる。
3. 区詳細: ヘッダーと区内目次が重ならず、各アンカーの見出しが隠れない。
4. おすすめ: rangeを親指で0→5まで動かしやすく、保存ボタンを誤タップしない。
5. ランキング: 横に送らなくても順位・地域・選択指標・信頼度が読める。
6. 条件比較: 横スクロールしても区名が左端に残る。
7. 駅/区詳細ダイアログ: 縦長コンテンツでも画面内でスクロールできる。
8. 250m地図: 地図上からそのまま縦スクロールへ復帰できる。
9. 低速回線: ホームで同じ `wards.json` を複数回取りに行かず、駅ページでも `geo/index.json` が重複取得されない。

## 今回は触らないもの

- Core Score / 駅スコアの計算ロジック
- 公開データの意味・集計範囲
- 250mメッシュの総合点/ランキング化
- 物件位置の推測

スマホ改善は表示・操作性・同一ページ内の転送効率だけに限定し、データ意味論は変更しない。
