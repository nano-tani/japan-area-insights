# 多角的詳細分析 設計

## 目的

既存の区・駅の総合100点は比較の入口として維持し、取得可能な公的データを総合点へ過剰に混ぜず、詳細ページで原数値・変化・サンプル数・出典・信頼度を確認できるようにする。

## 原則

1. 総合100点の6項目は当面変更しない。
2. 災害・都市計画は総合点に含めない。
3. 市区町村統計を250mメッシュへ推計配分しない。
4. XIT001の取引情報から物件位置を推測しない。
5. 各詳細指標に原典、原典年度、サンプル数、推計/実績、品質A-Dを保持する。
6. SQLite本体は公開せず、加工済みJSONだけをGitHub Pagesへ出す。

## 分析ブロック

### MARKET

XIT001の未活用属性を保存し、直近5完了年を基本期間として以下を集計する。

- 取引件数
- 取引単価中央値
- 取引面積中央値
- 中古マンション取引比率
- RC/SRC構造比率
- 改装済み比率
- 建物年齢中央値
- 前面道路幅員中央値

XPT002は区平均だけでなく地点データを保存し、以下を集計する。

- 最寄駅までの道路距離中央値
- 法定容積率中央値
- ガス・水道・下水道が全て整備された地点比率

XCT001鑑定評価書は全属性を `raw_json` として保存し、主要な鑑定価格を正規化する。

- 鑑定評価書件数
- 標準地価格中央値
- 取引事例比較法の比準価格中央値
- 収益価格中央値
- 収益価格算定あり比率
- 相続税路線価 / 公示価格比率

### MIGRATION

e-Stat住民基本台帳人口移動報告を用い、以下を区単位で保存する。

- 転入者数
- 転出者数
- 転入超過数
- 20〜39歳転入超過数
- 0〜9歳転入超過数

短期的な人口モメンタムとして扱い、将来人口推計とは別指標にする。

- 納税義務者1人当たり課税対象所得（派生指標）
- 財政力指数
- 実質公債費比率
- 将来負担比率
- 昼夜間人口比率
- 事業所数
- 従業者数
- 1事業所当たり従業者数

### HOUSING / LABOR / EDUCATION / HEALTH / WELFARE / CULTURE

- 空き家率
- 労働力人口
- 就業者数
- 労働力人口に占める就業者比率
- 最終学歴人口（卒業者総数）
- 大学・大学院卒業人口
- 大学・大学院卒業者比率
- 病院数
- 一般診療所数
- 病院病床数
- 医療施設医師数
- 人口1万人当たり病院病床数
- 人口1万人当たり医療施設医師数
- 老人福祉施設数
- 公民館数
- 図書館数

## 保存テーブル

- `dataset_catalog`: データセット、API ID、原典年度、粒度、更新モード
- `metric_definitions`: 指標名、単位、方向、最低サンプル数
- `metric_quality`: 指標ごとの品質A-D、原典年度、サンプル数、推計フラグ
- `land_price_points`: XPT002地点属性
- `appraisal_records`: XCT001鑑定評価書の主要正規化値 + 全属性JSON
- `spatial_features`: 都市計画・防災等のGeoJSON
- `geo_exposures`: 地理単位×レイヤーのメッシュ/人口曝露
- `geo_metrics`: 既存共通テーブルへ詳細指標を `detail-v1` として保存

XIT001詳細属性は既存 `transactions` に列を追加する。駅取引用 `station_transactions` にも同じ列を追加可能なスキーマにするが、区の詳細市場分析では市区町村指定XIT001のみを使用する。

## 公開JSON

- `web/data/analysis/catalog.json`
- `web/data/analysis/ward/<area_id>.json`

区詳細ページでは以下を独立ブロックで表示する。

- 不動産市場
- 人口移動
- 所得・自治体財政・昼夜間人口・事業所
- 住宅ストック
- 労働・教育
- 医療・福祉・文化
- 都市計画・災害曝露

指標ごとに期間、サンプル数、品質A-Dを併記する。

## 更新

`Refresh public data` の `extended_analysis=true` で拡張分析を取得する。同一Workflowで処理する理由は、SQLiteをGit管理せず、Workflow間でDBを永続化しないため。

駅指定XIT001では有効な駅コードでも対象年に取引が存在しない場合に404が返ることがあるため、400/404を空サンプルとして扱い、全体更新を継続する。

拡張APIで一時的な取得障害や統計表構造変更が発生しても、コアの区・駅データ更新を失敗させないよう拡張取得ステップは `continue-on-error` とし、取得できた詳細項目だけを公開する。

## 今後追加するデータ

共通基盤に追加可能だが、API呼出量・更新頻度・粒度を別途設計した方がよい候補:

- 建築着工統計の月次・市区町村別新築供給
- 経済センサスの産業大分類別構成
- 国勢調査の市区町村間通勤通学OD
- J-SHIS地震ハザード / 表層地盤
- 国土地理院標高

これらも総合100点へ自動的に混ぜず、粒度と意味に応じて詳細分析指標・曝露情報として追加する。
